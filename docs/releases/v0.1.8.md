# Sumpter v0.1.8 Release Notes

**Release Date:** 2026-06-08
**Theme:** Bounded-memory JSON/NDJSON output streaming, CI/local toolchain parity, and public-data corpus expansion
**Status:** Prepared for release

## Overview

v0.1.8 delivers the bounded end-to-end output streaming that v0.1.7 deferred.
JSON and NDJSON file output now streams through the `RecordSink` path for both
sequential and record-index parallel runs, so extraction memory stays bounded
instead of buffering every record per source file before writing.

The release has three threads:

1. **Bounded JSON/NDJSON output streaming.** Sequential and record-index
   parallel extraction emit records through the record-sink path; parallel runs
   preserve document order through a bounded reorder window. A memory-regression
   proof guards the bound.
2. **Streaming eligibility gating.** `min_occurrences` handling and a large-file
   gate decide when the bounded streaming route applies versus the buffered
   fallback, with a warning when a sequential run falls back to the buffered
   floor.
3. **CI/local toolchain parity and corpus expansion.** A checked-in toolchain
   contract makes local lint predict CI, and three public-domain XML exemplars
   widen the worked-example corpus.

## What's new

### Bounded JSON/NDJSON output streaming

Sequential JSON/NDJSON extraction streams emitted records through the
`RecordSink` contract introduced in v0.1.7 rather than accumulating a full
result slice per source file. Record-index parallel extraction streams through
a bounded reorder window that preserves source-document order without retaining
all records in memory.

Extraction memory for these paths is now bounded by parser state, active record
work, writer buffers, and — for parallel runs — the configured reorder window.
A memory-regression fixture asserts heap stays flat at scale so future changes
cannot silently reintroduce full-result buffering.

Capability boundary: the bound covers JSON/NDJSON sequential and record-index
parallel output. Parquet output, mixed-output runs (JSON/NDJSON **and**
Parquet), sequential `min_occurrences` paths, and ambiguous indexed-floor paths
remain buffered in v0.1.8 and stay on the buffered path by design.

### Streaming eligibility gating

`sumpter extract` now decides streaming eligibility explicitly. The streaming
route applies when the recipe and inputs qualify; otherwise the run uses the
buffered fallback. A `min_occurrences` floor and a large-file gate drive this
decision, and a sequential run that falls back to the buffered floor emits a
warning so the behavior is observable rather than silent.

### CI/local toolchain parity

`config/toolchain.env` is the checked-in contract for the Go and golangci-lint
versions used by local gates, CI, and release builds. `make toolchain-check`
verifies the local Go version, the `go.mod` toolchain directive, `GOFLAGS`, the
installed golangci-lint binary, and `.goneat/tools.yaml` against the contract
before linting; a mismatch fails with an actionable remediation command instead
of silently running a drifted toolchain.

golangci-lint installs via a pinned `go install ...@v2.11.2` path (no
brew/latest path), and CI and release workflows load the same contract. A
pinned-staticcheck probe (`make lint-staticcheck-probe`) asserts the `SA5011`
diagnostic is reported, directly covering the local/CI lint divergence
surfaced during the v0.1.8 streaming work.

### Public-data corpus expansion

Three public-domain XML exemplars join the worked-example corpus, each chosen
for a record shape distinct from the existing SEC EDGAR XBRL and ClinVar
examples:

- **USGS QuakeML** (geophysics) — scientific-measurement records with
  value/uncertainty leaf pairs and an extension-namespace on attributes.
- **NWS CAP** (public-safety geospatial) — Atom + `cap:` cross-namespace field
  mapping and a geospatial polygon literal as a first-class field.
- **GovInfo USLM** (government/legal) — a recursive legal-document grammar with
  stable hierarchical identifiers and mixed content.

Each ships a signature + extract recipe pair, a sliced public-domain sample, and
a runnable command in the public-data examples guide. The guide and README also
reframe the public-data positioning: the exemplars demonstrate domain-neutrality
(public-domain sources are used so every example ships runnable by anyone), and
public and proprietary formats are both first-class.

## Behavior changes

- **JSON/NDJSON output is bounded for sequential and record-index parallel
  runs.** Capacity planning for these paths can assume bounded output memory
  rather than per-file buffering.
- **Parquet, mixed-output, sequential `min_occurrences`, and ambiguous
  indexed-floor paths remain buffered.** These intentionally stay on the
  buffered path in v0.1.8.
- **Sequential buffered fallback now warns.** A sequential run that falls back
  to the buffered floor emits a warning.
- **Local lint can fail before linting on toolchain drift.** `make
toolchain-check` (run by `make lint` / `make check-all`) fails with a
  remediation command if local tools do not match `config/toolchain.env`.

## Deferred

- **Incremental Parquet writing** remains future work. Parquet stays a buffered
  secondary projection path until true incremental row-group writing lands.
- **Bounded mixed-output runs** remain future work. Requesting JSON/NDJSON and
  Parquet together keeps the run on the buffered path.
- **Bounded sequential `min_occurrences` and ambiguous indexed-floor paths**
  remain future work.
- **Cloud URI read/write (S3 and S3-compatible) input/output** is the next
  major capability thread and is tracked separately.
- **DuckDB, Arrow, service health endpoints, Prometheus metrics, adaptive
  backpressure, and repair modes** remain roadmap items.

## Upgrade notes

- **Version bump.** `VERSION` is `0.1.8`. Binaries from this tag emit `v0.1.8`
  via `sumpter version`.
- **Go installation.** v0.1.8 requires Go 1.26 or newer. After the tag is
  published, install with:

  ```bash
  go install github.com/fulmenhq/sumpter/cmd/sumpter@v0.1.8
  ```

- **Memory expectations.** Sequential and record-index parallel JSON/NDJSON
  output is now bounded. Keep buffered-path capacity planning for Parquet,
  mixed-output, sequential `min_occurrences`, and ambiguous indexed-floor runs.
- **Contributors.** Run `make toolchain-check` (or `make check-all`) to verify
  your local toolchain matches `config/toolchain.env`; see
  [`docs/standards/toolchain-contract.md`](../standards/toolchain-contract.md).
- **Release ceremony.** Use `SUMPTER_RELEASE_TAG=v0.1.8` for release targets.
  Tagging and pushing `v0.1.8` should happen only after CI, review, and the
  out-of-band public-surface/confidentiality checks are complete.

## Validation summary

The v0.1.8 cycle was validated through normal PR gates and final release-prep
checks:

- Bounded sequential and parallel JSON/NDJSON output streaming, with a
  memory-regression proof that heap stays flat at scale.
- Streaming-eligibility gating (`min_occurrences`, large-file gate) and the
  sequential buffered-fallback warning.
- Toolchain-contract verification, the pinned-staticcheck `SA5011` probe, and a
  negative mismatch check that fails before linting.
- Public-data exemplars validated end-to-end against current `main`.
- Release prep: version bump, release notes, changelog, embedded docs refresh,
  `make check-all`, and `make verify-embeds`.

Before tagging, CI must be green on the release-prep PR and the required
out-of-band security/confidentiality scans must be complete.
