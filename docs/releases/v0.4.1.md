# v0.4.1 — Inline-XBRL inventory and XML source fidelity

**Release status:** unreleased · **Lifecycle:** alpha (interface-stability track; external contributions welcome)

## Inline-XBRL inventory

Bundled recipes inventory strict XML documents using the existing XML DOM
route. The supported profile accepts uncompressed input no larger than
104,857,600 bytes (100 MiB) and binds inline-XBRL namespaces by URI.

Run the synthetic example:

```bash
sumpter recipes run extract examples/cases/16-inline-xbrl-inventory/recipe \
  --files examples/cases/16-inline-xbrl-inventory/input.xml \
  --output-path out/
```

The fact recipe projects `nonFraction`, `nonNumeric` and `fraction`, including
hidden and nested facts. Companion recipes project contexts, units,
continuations, footnotes, reference containers and relationships. Missing
attributes and present-empty attributes remain distinguishable.

Values and attributes remain strings. Text includes `ix:exclude` content;
continuations are not joined, numeric transforms are not applied, and QName
values retain their source spelling. Tuple, tupleRef and fact-level order are
outside this profile. Relationship order is inventoried. References are not
fetched or validated. Context and unit projections are not lossless XML
serialization or validated definitions.

These recipes use one descendant traversal and avoid XPath unions. They do
not fix general union ordering or establish this profile for streaming or
indexed extraction. There is no new input-format token or HTML-repair route.
See the [worked example](../../examples/cases/16-inline-xbrl-inventory/README.md)
and [application note](../appnotes/sourcedata/finance/inline-xbrl-inventory.md).

## XML source fidelity

Streaming and indexed XML scans accept ASCII and US-ASCII declarations without
transcoding source bytes or changing offsets and hashes. They reject
non-ASCII bytes under those declarations and encoding-label lookalikes.
UTF-8 handling remains unchanged.

## Recipe hash canonicalization

Recipe content hashes now use `github.com/3leaps/canonprims` for RFC 8785
(JCS) canonicalization. Canonical bytes and recipe hashes are unchanged for
every accepted input, including all bundled recipes.

**Compatibility change:** a recipe signature, extract or applicability asset
that contains a Unicode noncharacter (U+FDD0–U+FDEF, or any code point ending
in FFFE or FFFF) in a key or string value is now refused with a
`noncharacter` error. These characters are outside the I-JSON input domain that
RFC 8785 requires, so the hash cannot be relied on across implementations.
Previously such assets were hashed. Remove or replace the character in the
source asset and recompute the recipe hash; Sumpter does not rewrite assets.

## Remote input errors

Bounded remote reads keep typed `not found` and `permission denied` errors when
an object disappears or becomes unreadable between its metadata and content
requests. The input is recorded as `input_unavailable` instead of a parse error.

## Build and validation tooling

- Minimum Go version: 1.26.10.
- goneat: 0.6.6; golangci-lint: 2.14.0; CI runner images: fulmen-toolbox 0.5.14.
- Associated module dependencies are updated.
- Required confidentiality-check mode fails when the checker is unconfigured
  or cannot be admitted. See the [validation boundaries](../decisions/confidentiality-validation-boundaries.md).
- The staticcheck smoke probe uses SA4000. Upstream disabled SA5011, so this
  probe no longer provides nil-dereference coverage.
- The example canonicalization helper checks the same file it opened.
