# Sumpter v0.1.6 Release Notes

**Release Date:** 2026-06-01
**Theme:** Public-readiness, capability honesty, and streaming/index correctness
**Status:** Prepared for release

## Overview

v0.1.6 is the final release-prep step before the public repository transition.
It closes the release-readiness loop started in v0.1.5 by tightening Sumpter's
public capability surface, hardening selector and index behavior, and
documenting the confidentiality posture expected for the open-source
repository.

The release has four threads:

1. **Honest capability surface.** Documentation, schemas, and command outputs
   now describe what Sumpter ships today instead of overclaiming planned sinks
   or integrations.
2. **Correctness and safety hardening.** Record indexes no longer imply safe
   offsets for compressed inputs, streaming/index selectors reject unsupported
   XPath forms instead of silently over-matching, and final readiness fixes
   clarify existing behavior.
3. **Uniform per-record schema.** Declared output properties can be emitted
   consistently with explicit `null` values for absent fields, making downstream
   table ingestion less brittle.
4. **Public-readiness posture.** Governance docs, release gates, examples, and
   public-facing copy were aligned for an OSS surface that stays generic and
   keeps sensitive data outside the repository tree.

## What's new

### Honest public capability surface

v0.1.6 removes or restates claims that were ahead of the implementation:

- `envinfo` JSON output now validates against the shipped schemas.
- README and user-facing docs distinguish available NDJSON/Parquet behavior
  from planned analytics sinks and service integrations.
- The release notes and overview state the Go 1.26 floor clearly.
- Capability copy keeps the current memory contract explicit: XML input is
  tokenized incrementally, while extracted records are still buffered per file
  before output.

### Uniform per-record schema

Recipes can request a uniform output shape for extracted records. When enabled,
declared properties that are absent in a record are emitted as `null` rather
than disappearing from that record's payload. This gives table-oriented
consumers a stable column set without forcing recipe authors to synthesize
placeholder values in field mappings.

### Safer record indexes

Record index metadata now distinguishes physical source offsets from logical
record semantics more carefully. In particular, Sumpter avoids presenting byte
offsets from compressed sources as seekable positions for parallel extraction.
That prevents a class of unsafe compressed-source workflows where an index
appeared usable but could not safely support direct seeking.

### Restricted streaming/index selector grammar

Streaming extraction and `index build --selector` now share the same record
selector validator. For v0.1.6, streaming/index mode accepts only local element
selectors:

```text
Record
//Record
```

Predicates, multi-segment paths, namespace-prefixed forms, empty selectors, and
other XPath expressions fail loud with "not yet supported for streaming/index
mode" wording. Matching is exact and case-sensitive. This prevents silent
over-match behavior while leaving richer XPath forms available to non-streaming
extract paths.

### Release and confidentiality gates

The repository now includes a final `make pr-final` drift gate, refreshed OSS
metadata, and ADR-0008, which records that sensitive or proprietary data belongs
outside repository working trees. Operator-specific confidentiality scanning is
an out-of-band release-readiness step and remains separate from the public
repository configuration.

## Behavior changes

- **Go 1.26 is now the minimum supported Go version.** `go.mod` declares
  `go 1.26.0` with `toolchain go1.26.3`; CI and seekable-zstd integration
  containers build with Go 1.26.
- **Streaming/index selectors are intentionally narrower.** Unsupported XPath
  forms now fail instead of being reduced to a permissive local-name match.
- **XML local-name matching in streaming/index mode is case-sensitive.** This
  follows XML name semantics and avoids matching `Record` and `record` as the
  same element.
- **Compressed-source indexes are not advertised as seekable extraction inputs.**
  Sumpter keeps compressed-source safety explicit rather than implying direct
  byte seeking is possible.
- **Documentation now treats planned sinks and service integrations as roadmap
  items.** Shipped outputs remain structured JSON, NDJSON, and recipe-declared
  Parquet projections.

## Deferred

- **Record-sink output streaming** is deferred to v0.1.7 or later. v0.1.6 keeps
  the honest memory contract: input tokenization is streaming, extracted records
  are buffered per file before output.
- **Index streaming follow-up work** is deferred to v0.1.7 or later.
- **DuckDB, Arrow, service health endpoints, Prometheus metrics, adaptive
  backpressure, and repair modes** remain roadmap items.

## Upgrade notes

- **Version bump.** `VERSION` is `0.1.6`. Binaries from this tag emit `v0.1.6`
  via `sumpter version`.
- **Go installation.** v0.1.6 requires Go 1.26 or newer. After the tag is
  published, install with:

  ```bash
  go install github.com/fulmenhq/sumpter/cmd/sumpter@v0.1.6
  ```

- **Selector review.** If a streaming/index workflow used selectors with
  predicates, paths, prefixes, or other XPath expressions, simplify the
  streaming/index record selector to `Name` or `//Name` before upgrading.
- **Uniform schema opt-in.** Recipes that benefit from stable table columns can
  enable the uniform-schema behavior and should verify downstream consumers
  distinguish absent/null values correctly.
- **Release ceremony.** Use `SUMPTER_RELEASE_TAG=v0.1.6` for release targets.
  Tagging and pushing `v0.1.6` should happen only after CI, review, and the
  out-of-band confidentiality/security scan are complete.

## Validation summary

The v0.1.6 cycle was validated through normal PR gates and final release-prep
checks:

- Public-readiness metadata, security/dependency posture, and final PR drift
  gating.
- Correctness sweep around retrieval, DSL defaults, and memory-contract wording.
- Uniform per-record schema behavior with focused tests.
- Record-index offset semantics and compressed-source safety.
- Streaming/index selector hard errors, shared validation, and config clone
  immutability regressions.
- Release prep: Go 1.26 floor, release notes, changelog, embedded docs refresh,
  `make check-all`, and `make pr-final`.

Before tagging, CI must be green on the release-prep PR and the
operator-managed out-of-band security/confidentiality scans must be complete.
