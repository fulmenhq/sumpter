# v0.3.4 — Bounded cloud extract; logical reader and writer handles

**Released:** 2026-09-04 · **Lifecycle:** alpha (interface-stability track; external contributions welcome)

v0.3.4 makes **bounded cloud extract** a first-class `extract-multi` path.
`s3://` objects listed in a URI `--file-list` can be acquired just-in-time
under run-global staging byte and file caps plus a per-object max, instead of
staging the whole list first. Eager staging remains the default.

The shared CLI selects the **reader** handle. Each recipe declares its own
**writer** handle. There is no shared `--output-credentials-handle` on
`extract-multi`. Cloud aggregate still requires a positive
`--aggregate-max-bytes` at or below the 5 GiB single-PUT ceiling.

**Start here:** [`docs/extract-workflow.md`](../extract-workflow.md)
(bounded cloud input and extract-multi examples).

## Tested topology

This cut was verified as:

- bounded cloud URI-list input to **local** aggregate output, including a
  100,000-object run with exact byte and record reconciliation and zero
  failures;
- bounded cloud URI-list input to **cloud** aggregate output, including a
  1,000-object canary whose published objects were read back by size and
  digest;
- distinct **logical** reader and writer handles (the writer handle is
  recipe-owned; the reader handle is the shared CLI selection).

A live writer in a **different account** than the reader was not proven.
Do not describe this release as cross-account validated.

Hermetic coverage includes eager/bounded local parity, a generated 7 MiB
object admitted under an 8 MiB cap, loud pre-stage refusal above that cap
with staging cleanup, and a record-dense `FixtureDocument` that stays
inside the existing per-input bundle contract.

## Compatibility & notes

- **Eager default unchanged.** `--cloud-input-mode bounded` is opt-in.
- **Handle split is extract-multi only.** Single-recipe `extract` still
  takes both `--input-credentials-handle` and `--output-credentials-handle`.
- **Platforms:** unchanged — linux amd64/arm64, darwin **arm64**, windows
  amd64/arm64. Intel-Mac users build from source.
- **Alpha:** interfaces may still change between minor releases; external pull
  requests are welcome.

## Deferred / follow-ups

- Nested item/polymorphic `internal: true` remains deferred.
- Process-run control socket / run-steering (unchanged from v0.3.1–v0.3.3).
- Richer data-artifact validation and full semantic L3 claims (unchanged).
- Million-object bounded-cloud characterization is not a gate for this cut.
- Cloud range-reads, GCS/Azure, DuckDB/Arrow, service health endpoints, and
  repair modes remain roadmap items.
