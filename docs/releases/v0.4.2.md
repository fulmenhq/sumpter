# v0.4.2 — XPath union document order, string/regex contract, and external recipe guides

**Release date:** 2026-11-08 · **Lifecycle:** alpha (interface-stability track; external contributions welcome)

## XPath union document order

Union expressions (`A | B`, `(A | B)[1]`, `string(A | B)`, and record-boundary
`match_selectors` unions on the DOM route) now return deduplicated nodes in
source document order rather than left-to-right operand order across DOM,
indexed parallel, and streaming extraction routes.

**Compatibility change:** an unguarded union `(Primary | Fallback)[1]` or
`string(Primary | Fallback)` no longer acts as a left-to-right priority
fallback. When both nodes exist in a record, the union returns whichever node
appears first in the source document. To express priority fallback independent
of element order in the input, use either:

- a guarded union with mutually exclusive branches:
  `string(Primary | Fallback[not(../Primary)])`
- two `internal: true` field mappings (`primary`, `fallback`) combined in the
  Sumpter DSL: `primary != "" ? primary : fallback`

On the pinned `antchfx/xpath` engine (`v1.3.8` plus the merged upstream union
document-order fix), two expression shapes remain outside document-order union
support and should be avoided in recipes:

- relative grouped `[last()]` or `[position() = N]` inside a union branch (such
  as `./a | (./b)[last()]`), which evaluates against the outer context size
- single-operand reverse-axis unions (such as
  `preceding-sibling::*[1] | self::node()[false()]`), which reverse axis step
  order before the positional predicate is applied; use the reverse axis
  directly without wrapping it in `|`

See [XPath union (`|`) document order and priority fallback](../extract-workflow.md#xpath-union--document-order-and-priority-fallback)
and the [Case 20 worked example](../../examples/cases/20-ordered-fallback-and-ancestor/README.md).

## XPath string and regular-expression function contract

Sumpter now documents and enforces the promised XPath function contract in
`field_mappings[].xpath` (including nested `item_mapping` field mappings) across
DOM, indexed parallel, and streaming routes:

- **XPath 1.0 string and coercion functions:** `string`, `concat`,
  `starts-with`, `contains`, `substring-before`, `substring-after`, `substring`,
  `string-length`, `normalize-space`, `translate`, `number`, and `boolean`
- **Selected XPath 2.0 extensions:** `lower-case(s)`, `ends-with(s, suffix)`,
  `matches(s, 'pattern')`, and `replace(s, 'pattern', 'replacement')`

**Compatibility change (load-time admission):** recipe and extract-config load
now validates supported string/coercion function arities and requires the
pattern argument of `matches`/`replace` and the replacement argument of
`replace` to be string literals. Patterns are compiled with Go `regexp` (RE2) at
load, and `replace` templates are checked against the compiled pattern's capture
groups:

- Literal `$` is written `$$` (avoid `$$<digit>` when the pattern has capture
  groups; use a non-capturing group `(?:...)` instead).
- Whole-match substitution is `$0` or `${0}`; when followed by a Unicode
  letter, digit, or `_`, use braced `${0}` (for example `${0}USD`).
- Numbered capture groups `1`..`9` use `$1`..`$9` (when not followed by a digit)
  or `${1}`..`${9}`; groups `10` and above require braced `${10}`..`${N}` with
  no leading zeros.
- Named capture groups `(?P<name>...)` use `${name}`.
- Backslash escapes (`\$`), trailing `$`, leading-zero numeric references
  (`$01`, `${01}`), unbraced multi-digit references (`$10`), unbraced `$name`,
  and out-of-range group numbers are refused at load.

Unexpected runtime evaluator panics (such as out-of-range 3-argument
`substring('abc', 2, 100)` slice bounds on `antchfx/xpath v1.3.8`) are
recovered and returned as field-attributed extraction errors rather than
crashing the process.

Documented `v1.3.8` engine caveats remain in effect until a full `antchfx/xpath`
module upgrade: `string-length`, `substring`, and `translate` operate on UTF-8
byte offsets rather than Unicode code points; `normalize-space` collapses all
`unicode.IsSpace` characters (including `U+00A0`); and `matches(Missing, ...)`
on an absent bare node-set returns `false` without matching against `""` (wrap
in `string(...)` or `normalize-space(...)` when an absent node should be tested
as `""`). See the
[XPath string and regular-expression function contract](../extract-workflow.md#xpath-string-and-regular-expression-function-contract)
and [DSL reference](../dsl-reference.md#xpath-string-and-regular-expression-functions-in-field_mappingsxpath).

## XPath numeric coercion and NaN guard

XPath 1.0 `number()` converts empty, whitespace-only, absent, or non-numeric
text (such as `"-"`, `"N/A"`, or currency-prefixed strings) to IEEE 754 `NaN`,
which fails JSON/NDJSON output serialization (`json: unsupported value: NaN`).

To guard numeric coercion directly in XPath across whitespace-padded, signed,
decimal, empty, absent, and placeholder values:

```yaml
xpath: "number(replace(normalize-space(Amount[matches(normalize-space(.), '^-?[0-9]+(\\.[0-9]+)?$')]), '^$', '0'))"
```

Alternatively, extract the trimmed string into an `internal: true` staging field
and apply a Sumpter DSL conditional before `to_number(...)`. See
[XPath numeric coercion and `NaN` guard](../extract-workflow.md#xpath-numeric-coercion-and-nan-guard).

## External recipe workspace and extract command guides

Two new embedded user-guide pages cover external recipe authoring and the
`extract` command family:

- [External recipe workspaces](../user-guide/recipes.md)
  (`sumpter docs show user-guide/recipes.md`) — directory layout, what

  (`sumpter docs show user-guide/commands/extract.md`) — flags, input discovery,
  `--output-mode` (`per-file` and `aggregate`, both writing `manifest.json`
  while `--no-manifest` is refused), `--record-index`, and `--validate-output`.

## Worked examples

Run the new XPath string/regex and `NaN`-guard example:

```bash
sumpter recipes run extract examples/cases/17-xpath-string-and-regex/recipe \
  --files examples/cases/17-xpath-string-and-regex/input.xml \
  --output-path out/
```

New positive and negative cases in [`examples/README.md`](../../examples/README.md):

- `17-xpath-string-and-regex` — XPath 1.0 string functions, `lower-case`,
  `ends-with`, `matches`, `replace`, and whitespace-safe `NaN`-guarded numeric
  coercion
- `18-per-record-verdict-matrix` — `internal: true` derive-only staging, list
  parameters (`starts_with_any`, `value_in`), ternary verdict classification,
  and `value_profile` outcome counts
- `19-per-file-outcome-summary` — document-scoped `array_path` outcome summary
  and remainder rollups
- `20-ordered-fallback-and-ancestor` — guarded priority fallback, document-order
  unions, and `ancestor::` / `preceding-sibling::` navigation
- `21-signed-sum-and-epsilon` — context-sensitive signed XPath sums and
  cent-rounded epsilon reconciliation
- `98-negative-nan-numeric-field` — unguarded `number()` producing `NaN` fails
  record serialization before publication
- `99-negative-invalid-xpath-regex` — invalid or non-literal regex in
  `field_mappings[].xpath` is refused at recipe load
