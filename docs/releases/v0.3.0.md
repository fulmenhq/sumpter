# v0.3.0 — Portable data-artifact producer profile

**Released:** 2026-07-10 · **Lifecycle:** alpha (interface-stability track; external contributions welcome)

v0.3.0 makes Sumpter extract output **portable and legible** under the host-less
`contract: data-artifact/v0` capability. Catalogs, query engines, and data planes
that understand that contract can read opted-in bundles without Sumpter-specific
knowledge. The producer profile string on the wire is
`sumpter.extract-artifact/v0`.

The release is **additive and opt-in**. A run that never sets
`--artifact-descriptor`, never enables `defaults.value_profile`, and leaves
`--validate-output` at `off` is intended to stay compatible with pre-0.3.0 extract
output (including ordinary Parquet page statistics).

This is **baseline-bound structural producer adoption**: descriptors and catalogs
validate against the pinned contract bundle and follow the protection floors
below. It is not a claim of full semantic L3 export-gate conformance for every
grain shape. The adoption guide is
[`docs/data-artifact-producer-profile.md`](../data-artifact-producer-profile.md).

## Features

### Host-less contract baseline

Extract resolves `data-artifact/v0` from an explicit local `--contract-base`
directory (`contract.json` + entry schema). Production publish is
**baseline-gated**: the resolved bundle must match Sumpter's pinned Crucible
release and resolved-bundle SHA-256, not merely any directory that advertises the
capability. The current pin is Crucible **`v0.1.19`** with:

```text
sha256:37eca167cfa9a86357c14239eb9c3274c40c5cfee48f48ebb81480d737104b82
```

How that digest is computed is documented under
[Data Artifact Contract Baseline Hash](../user-guide/commands/validate.md#data-artifact-contract-baseline-hash).
The tree `tests/fixtures/data-artifact-contract/v0` is a CI / offline conformance
input that matches the pin — not an independently evolving runtime identity.

### Artifact descriptor and grains

With `--artifact-descriptor` (and `--contract-base`), extract writes
`artifact-descriptor.json` beside the provenance manifest after validating the
payload against the pin.

| Condition | Grain behavior |
| --- | --- |
| Default / per-input extract | Primary grain `kind: record_stream` |
| `--output-mode aggregate` | Primary grain becomes `kind: aggregation` (same protection floors — no lineage laundering). Multi-shard runs mark representations `sharded` and attach per-shard digests when present. |
| `--record-index` | **Additional** `object_index` grain for the **record-index file consumed** by indexed extraction. The URI is path-sanitized; Sumpter does not copy the index into the output bundle and does not promise the basename resolves beside the descriptor. |

Identity is non-deterministic (`artifact_id` is a fresh UUID URN per run).
Integrity is carried by digests where present.

### Field catalog sidecar

With the descriptor enabled, extract also writes `fields/records.fields.json`
(referenced from the descriptor; not embedded on the production path).

- Source-structure-derived keys (xpath / description) are **withheld by count**,
  not listed by name.
- Disclosed fields default to `sensitivity: unknown` and
  `export_action: block_export` (default-deny).
- A fully withheld catalog (`fields: []` + positive withheld count) is valid
  under the pinned baseline.

### Portable lifecycle

Descriptor `lifecycle` maps from existing provenance completeness signals —
no second accounting system:

| Provenance signal | `lifecycle` |
| --- | --- |
| `incomplete: true` | `incomplete` |
| Any failed inputs | `partial` |
| Otherwise | `complete` |

### Publication integrity

Local record outputs, Parquet files, and portable sidecars finalize with
same-directory **temp + rename**. Parquet is renamed into place only after the
writer closes successfully. Generated catalog and descriptor payloads are
validated against the pin **before** publish; the catalog is published **before**
the descriptor that references it. Cloud destinations validate complete staging
**before** Publish.

In aggregate mode, a failed run that already published cloud shards may emit
`incomplete: true` on the provenance manifest solely to inventory those shards.
Treat `incomplete: true` as a **failed** run, not as successful output.

### Protection declarations and writer-side metadata suppression

Two layers:

1. **Portable declarations** — protection metadata on the descriptor and field
   catalog. Consumers and data planes **enforce** export and read policy.
2. **Producer-side physical controls** — when `--artifact-descriptor` is on, the
   Parquet writer suppresses page bounds and page statistics on every leaf and
   never configures Bloom filters.

Default posture includes top-level `block_export` / `internal`, row-level
enforceable granularity for NDJSON, column-level for Parquet-with-descriptor,
and `columnar_scan` only (no `predicate_pushdown` claim without a matching
`pushdown_withheld` set). Recipe
`defaults.output.parquet.withhold_columns` remains a stronger, separate control
that drops named columns from the Parquet projection entirely.

### Opt-in `--validate-output` ladder

| Mode | Checks |
| --- | --- |
| `off` (default) | No extra output validation |
| `sidecars` | Provenance `manifest.json`; `failures.json` / `dispositions.json` when present |
| `artifact` | `sidecars` plus generated descriptor and field catalog (requires `--artifact-descriptor` and `--contract-base`) |
| `envelope-sample` | `artifact` plus sampled NDJSON envelopes (first, every 100th, last) |
| `strict` | `artifact` plus **every** NDJSON record envelope |

Standalone: `sumpter validate artifact-descriptor … --contract-base …`.

These modes provide **baseline-bound structural / schema validation** (plus
envelope checks on higher rungs). They are **not** a complete L3 semantic or
consumer export-gate validator.

### Guarded provenance `value_profile`

Optional diagnostic on the **provenance** manifest (not the artifact
descriptor), enabled via recipe `defaults.value_profile`.

- **Tier A (concrete values)** only when `safe_to_profile` **and** sensitivity is
  `public` or `internal` **and** distinct count is **at or below** `max_distinct`.
- **Never-enumerate tags** (`direct_identifier`, `source_structure`,
  `opaque_payload`, `access_control_metadata`) force aggregates-only even if
  public + safe_to_profile is set.
- **Tier B** emits counts, capped distinct form, length stats, and coarse shape —
  never sample values, top-K, or string min/max.
- Field classification is **operator-declared**; enabling the feature is not a
  blanket “safe on any field.”
- Disabled / omitted → no `value_profile` field (byte-identical manifests).

Observation is exactly-once per committed logical record. Failed or
floor-rejected inputs discard staged observations.

## Compatibility & notes

- **All-additive / byte-compatible default path.** Adopting none of the new
  surfaces leaves pre-0.3.0 extract behavior.
- **Two identities.** `contract: data-artifact/v0` selects the portable contract;
  `sumpter.extract-artifact/v0` identifies this producer profile.
- **Validation altitude.** Descriptor validation is structural and baseline-bound,
  not full consumer-policy enforcement.
- **object_index honesty.** The shipped index grain describes a consumed input
  reference; catalog-less object indexes are structurally valid but contract prose
  for fully queryable indexes may still require catalog or lineage refinements.
- **Sharded aggregates.** Opaque shard-id / count-expectation carriers for full
  L3 multi-shard semantics remain follow-on.
- **Platforms:** unchanged from 0.2.x — linux amd64/arm64, darwin **arm64**,
  windows amd64/arm64. Intel-Mac users build from source.
- **Alpha:** interfaces may still change between minor releases; external pull
  requests are welcome.

## Migration guidance

No migration is required for existing recipes or runs. To adopt the portable
profile:

1. Vendor or obtain a contract base that matches the pinned Crucible release /
   resolved-bundle hash.
2. Pass `--artifact-descriptor --contract-base <dir>` on extract (requires
   `--output-path` and a normal provenance manifest).
3. Optionally enable `--validate-output artifact` (or higher) and recipe
   `defaults.value_profile` as needed.

See the
[Data-Artifact Producer Profile](../data-artifact-producer-profile.md) guide and
[Extract Workflow](../extract-workflow.md) for operational detail.

## Deferred / follow-ups

- Richer validation strictness, cross-artifact lineage, and reserved
  disclosure-control / lineage slot activations.
- Sibling **process-run/v0** portable run observability and control (separate
  track).
- Full semantic L3 conformance claims for every grain shape.
- Cloud range-reads, cloud-side indexing, GCS/Azure providers, DuckDB/Arrow,
  service health endpoints, and repair modes remain roadmap items, as in 0.2.x.
