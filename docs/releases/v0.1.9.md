# Sumpter v0.1.9 Release Notes

**Release Date:** 2026-06-09
**Theme:** Complete the release artifact matrix — windows-arm64
**Status:** Prepared for release

## Overview

v0.1.9 is a small, front-loaded distribution patch. It closes the one gap in
Sumpter's published binary matrix: the release now ships
`sumpter-windows-arm64.exe`, so all six raw binaries
(linux/darwin/windows × amd64/arm64) are present and arch-complete.

This release deliberately precedes the Homebrew + Scoop wiring (next cycle): the
package-manager formula and manifest reference these published assets by URL, so
the full matrix must exist and be published first. Proving we can produce every
artifact we need — before building the package-manager-specific tooling —
de-risks that work.

There are no product-code changes in this release.

## What's new

### `windows-arm64` release binary

`make release-build` and `make build-all` now emit
`sumpter-windows-arm64.exe` alongside the existing five targets. The binary
cross-compiles on the pure-Go path (`release.yml` pins `CGO_ENABLED=0`; the index
store falls back to the JSON path when CGO is disabled), so no new dependencies
or build steps are required — Go has supported `windows/arm64` since Go 1.17 and
the pinned toolchain is well past that.

The existing provenance flows through unchanged: `SHA256SUMS`/`SHA512SUMS` (and
their `.asc`/`.minisig` signatures), `sumpter-minisign.pub`, and
`sumpter-release-signing-key.asc` all glob over the release directory, so the new
binary is covered with no tooling change.

### Release artifact matrix (end state)

| OS      | amd64                         | arm64                          |
| ------- | ----------------------------- | ------------------------------ |
| linux   | `sumpter-linux-amd64`         | `sumpter-linux-arm64`          |
| darwin  | `sumpter-darwin-amd64`        | `sumpter-darwin-arm64`         |
| windows | `sumpter-windows-amd64.exe`   | `sumpter-windows-arm64.exe` ⬅ new |

### GitHub Actions runtimes on Node 24

The three JS actions in CI and release workflows moved to their current Node-24
majors — `actions/checkout` (v4→v6), `actions/setup-go` (v5→v6), and
`softprops/action-gh-release` (v2→v3) — clearing the GitHub Actions Node-20
runtime deprecation (Node 20 is forced to Node 24 on 2026-06-16). The
`action-gh-release` v3 bump is a pure runtime move with no change to release
publishing behavior.

## Behavior changes

- **Windows-on-ARM is now a published target.** Windows/ARM64 users get a native
  binary directly from the release instead of relying on emulation of the amd64
  build.
- **No product-code or output-format changes.** Extraction, indexing, and CLI
  behavior are identical to v0.1.8.

## Deferred

- **Homebrew + Scoop wiring** is the next cycle (v0.1.10). It depends on this
  release's published assets.
- **Cloud URI read/write (S3 and S3-compatible) input/output** remains the next
  major capability thread and is tracked separately.

## Upgrade notes

- **Version bump.** `VERSION` is `0.1.9`. Binaries from this tag emit `v0.1.9`
  via `sumpter version`.
- **Go installation.** After the tag is published, install with:

  ```bash
  go install github.com/fulmenhq/sumpter/cmd/sumpter@v0.1.9
  ```

- **Windows/ARM64 download.** The release now includes
  `sumpter-windows-arm64.exe` with matching `SHA256SUMS`/`SHA512SUMS` entries and
  signatures.
- **Release ceremony.** Use `SUMPTER_RELEASE_TAG=v0.1.9` for release targets.
  Tagging and pushing `v0.1.9` should happen only after CI, review, and the
  out-of-band public-surface/confidentiality checks are complete.

## Validation summary

- `make release-build` produces all six raw binaries, including
  `sumpter-windows-arm64.exe` (verified `PE32+ executable Aarch64, for MS
  Windows`), with `SHA256SUMS`/`SHA512SUMS` covering all six and
  `make release-verify-checksums` passing.
- `make check-all` and `make verify-embeds` green; confidentiality tree check
  passes.
- No product-code changes; no confidentiality-posture impact.

Before tagging, CI must be green on the release-prep PR and the required
out-of-band security/confidentiality scans must be complete.
