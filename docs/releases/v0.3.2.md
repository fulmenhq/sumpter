# v0.3.2 — Same-record helpers without stray columns, and correct XPath sign arithmetic

**Released:** 2026-07-15 · **Lifecycle:** alpha (interface-stability track; external contributions welcome)

v0.3.2 is for recipe authors who need **same-record helpers without stray
columns**, and for anyone whose XPath multiplies a predicated `sum(...)` by a
context-sensitive factor. Two practical outcomes:

1. Mark a top-level `field_mappings` entry `internal: true` — compute a sign
   factor (or other intermediate) once, reuse it from later expressions, and
   never emit a column or portable field-catalog entry.
2. Field-mapping XPath arithmetic now evaluates operands against the correct
   node context — **no more silent-wrong sign totals** that still look green.

Under the hood the release is **additive** for the internal-mapping surface
(defaults stay byte-compatible when unused) and **corrective** for the XPath
arithmetic class that previously produced wrong numbers under the stock xpath
engine. No process-run or data-artifact contract pin changes in this cut.

**Start here:** [`docs/extract-workflow.md`](../extract-workflow.md) covers
derive-only field mappings and factor-first XPath authoring. Portable-output
and flight-recorder docs from v0.3.0 / v0.3.1 are unchanged.

## Features

### Derive-only field mappings (`internal: true`)

Need a sign factor or scaled intermediate on the same record without polluting
NDJSON/Parquet or the portable field catalog? Top-level `field_mappings[]`
entries may set `internal: true` so a helper is:

- computed into same-record expression scope (XPath phase first, then
  expressions in declaration order);
- projected out **before** filters, uniform-schema fill, output-schema
  validation, enrichment, value_profile, and all sinks;
- omitted from NDJSON/JSON bodies, Parquet columns, `field_provenance`
  **entries**, and the portable field catalog;
- invalid as a `value_profile.fields` subject (plan-load fails loud).

Expression-only internals are allowed. Nested item/polymorphic internals are
rejected. Internal names must not appear in `output_schema` properties/required
or filter keys. **Internal field names are not confidential** — they may still
appear in recipe provenance YAML and in emitted fields' expression lineage;
do not put secrets in field names.

### XPath numeric operand context isolation (`xpath-sum-multiply`)

Field-mapping XPath of the form

```text
sum(.//Entry[predicate]/Amount) * (1 - 2*count(self::…))
```

could evaluate the trailing factor against the wrong node when the left
operand carried a predicate, producing silently wrong numbers while extract
still succeeded. v0.3.2 pins a reviewed interim `github.com/antchfx/xpath` tree
under `./third_party/antchfx-xpath` with focused operand-context isolation
(`xmlquery` remains v1.5.1). Hermetic regressions cover the prepared field path
and signature/applicability selectors of the same class. Prefer factor-first
authoring for context-sensitive multipliers when running against older
binaries; trailing factors are correct on this pin.

Pin notes and the path to retire the replace when upstream tags a fix live in
`third_party/antchfx-xpath/SUMPTER-PIN-README.md`.

### Developer quality gate

Local pre-push validation now checks the full tree for format drift so a
feature branch that only touched a subset of packages cannot land with
unrelated formatting drift.

## Compatibility & notes

- **Internal mappings:** all-additive / byte-compatible when no mapping sets
  `internal: true`. Feature-scoped prepare rules (duplicate names, output-schema
  exclusion, external name reservation) apply only when at least one internal
  mapping is present.
- **XPath arithmetic:** expressions that relied on the old silent-wrong context
  behavior will change numeric results to the correct evaluation. Recipes that
  already used factor-first forms or non-context-sensitive factors are
  unaffected in practice.
- **Platforms:** unchanged — linux amd64/arm64, darwin **arm64**, windows
  amd64/arm64. Intel-Mac users build from source.
- **Alpha:** interfaces may still change between minor releases; external pull
  requests are welcome.

## Migration guidance

No migration is required for recipes that do not opt into `internal: true`.

**Minimal enable — derive-only helper:**

```yaml
field_mappings:
  - output_field: sign_factor
    xpath: "1 - 2*count(self::RefundEvent)" # synthetic
    type: number
    internal: true
  - output_field: raw_amount
    xpath: ".//Amount"
    type: number
  - output_field: amount
    expression: "sign_factor * raw_amount"
    type: number
```

`sign_factor` is available to later expressions and never appears as a column or
catalog field. For context-sensitive XPath factors, prefer factor-first forms
(see extract workflow) or rely on the corrected engine behavior for trailing
factors.
