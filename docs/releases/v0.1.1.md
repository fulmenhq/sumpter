# Sumpter v0.1.1 Release Notes

**Release Date:** 2025-10-13
**Theme:** Hybrid Streaming XML Architecture & Recipe System

## Overview

Sumpter v0.1.1 introduces a groundbreaking hybrid streaming architecture that enables constant-memory processing of extremely large XML files (50GB+), achieving a 99.95% memory reduction. This release also delivers a comprehensive recipe system for workflow automation and establishes a robust test foundation with 50% coverage.

## Hero Feature: Hybrid Streaming XML Architecture

### The Problem
Traditional DOM-based XML parsing requires loading entire documents into memory, making it impossible to process large files (50GB+) without massive memory footprints (111GB+ RSS).

### The Solution
ADR-0005 introduces a hybrid approach combining:
- **SAX-style streaming** for record discovery with constant memory
- **DOM parsing** for individual record processing
- **Automatic mode selection** based on file size

### Performance Impact
- **Memory Reduction:** 111GB → 50MB RSS (99.95% reduction)
- **File Size Support:** Tested with 50GB XML files
- **Threshold:** Automatic streaming for files >100MB with `--allow-large-files`

### Technical Architecture
```
┌─────────────────┐
│  Input File     │ (50GB XML)
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ RecordScanner   │ ← Token-by-token streaming
│  - XPath select │ ← Constant memory buffer
│  - Compression  │ ← Transparent .gz support
└────────┬────────┘
         │
         ▼ (one record at a time)
┌─────────────────┐
│  DOM Parser     │ ← Full structure for record
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Extract & Save  │ ← NDJSON output
└─────────────────┘
```

### Usage
```bash
# Automatic streaming for large files
sumpter extract \
  --signature-config sig.yaml \
  --extract-config extract.yaml \
  --input-path /data \
  --allow-large-files
```

## Recipe System

New `recipes` command provides manifest-based workflow automation:

### Commands
- **`recipes init`**: Scaffold new recipe workspaces with templates
- **`recipes run extract`**: Execute extract recipes with manifest defaults
- **`recipes retrieve`**: Acquire data from APIs and file systems

### Example Recipe Manifest
```yaml
version: recipe/v0.1.0
kind: extract
id: sample_extract
assets:
  signature: signature/sample-v01.yaml
  extract: extract/sample.yaml
defaults:
  input:
    path: testdata
    include_pattern: "*.xml"
  workers: 4
  progress: true
```

## Technical Details

### Architecture Decisions
- **ADR-0005**: Hybrid Streaming XML Architecture
  - Problem: Memory constraints for large XML files
  - Solution: SAX discovery + DOM record processing
  - Tradeoffs: Slight latency increase vs massive memory savings

### Dependencies
- No new external dependencies
- Pure Go implementation for streaming

### Compatibility
- Backward compatible with v0.1.0
- Streaming mode is opt-in via `--allow-large-files`
- Legacy DOM mode remains default for files <100MB

## Migration Notes


Convert existing extract workflows to recipes:

```bash

# Run with manifest defaults
sumpter recipes run extract . --progress
```

## Performance Benchmarks

### Memory Usage (50GB XML file)
- **Legacy DOM mode:** 111GB RSS (would OOM on most machines)
- **Streaming mode:** 50MB RSS (99.95% reduction)

### Processing Speed
- Streaming adds minimal latency (~5-10%) due to token parsing
- Throughput: ~500MB/min on standard hardware
- Scales to files of arbitrary size

## Known Limitations

1. Streaming mode requires `--allow-large-files` flag (safety default)
2. Attribute preservation in streaming currently limited to element-level
3. XPath selector must identify complete record boundaries
