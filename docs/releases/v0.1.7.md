# Sumpter v0.1.7 Release Notes

**Release Date:** 2026-06-02
**Theme:** Public flip, document-order semantics, streaming groundwork, and index-scale hardening
**Status:** Prepared for release

## Overview

v0.1.7 is the public-flip release. It closes the final documentation and
developer-experience gaps after v0.1.6, while landing the next layer of
streaming architecture without overstating the memory contract.

The release has four threads:

1. **Stable emitted-record semantics.** Single-selector extraction paths now
   preserve source-document output order and assign `_runtime.record_num`
   before filters run, leaving intentional gaps for filtered or skipped source
   records.
2. **Record-sink streaming groundwork.** ADR-0009 defines the emitted-envelope
   sink contract, and sequential sink primitives establish the implementation
   shape for future bounded JSONL/NDJSON output paths.
3. **Streaming index build.** Record-index writers can stream JSON and
   seekable-zstd artifacts during `index build`, with transactional publish
   behavior that preserves existing outputs on failure.
4. **Public-surface and DX cleanup.** Documentation and examples use generic
   public-surface language, and local formatter tooling now respects Git ignore
   rules so private scratchpads stay out of release-prep noise.

## What's new

### Document-order record semantics

For recipes with one record-boundary selector, regular DOM extraction,
streaming extraction, and indexed parallel extraction now share the same
emitted-record ordering contract:

- emitted records preserve source-document order;
- `_runtime.record_num` is 1-based and assigned before filters run;
- filtered or skipped source records leave gaps; and
- surviving records are never renumbered by output writers.

This gives downstream consumers a stable source-position field without forcing
them to infer order from output line numbers or worker completion order.

### Record-sink streaming contract and primitives

ADR-0009 defines the `RecordSink` contract for future output streaming work.
Sinks receive already-enriched emitted envelopes, preserve ordering and
`record_num` gaps, apply bounded backpressure, and treat write/finalize errors
as fatal output failures. Sequential sink primitives landed as implementation
groundwork in the same release cycle.

Capability boundary: v0.1.7 does **not** claim bounded end-to-end output memory.
XML input tokenization is incremental, but command paths still buffer extracted
records per source file before writing JSONL/NDJSON and optional Parquet
outputs. The release ships the contract and groundwork, not the final
bounded-output implementation.

### Streaming index writers

`sumpter index build` can now stream record-index metadata to JSON and
seekable-zstd writers as records are discovered. The builder keeps summary
accounting incremental and only retains record sizes when exact percentile
flags require it.

Index artifact publication is transactional: writers prepare temporary outputs,
commit only after every writer is ready, and keep rollback state until all
writers complete. Parse errors, later-writer start failures, and later-writer
commit failures no longer leave corrupt final artifacts or clobber previously
valid outputs.

### Public surface and formatter scope

Public documentation, examples, and release-facing copy were scrubbed to keep
the open-source surface generic. Release tooling also now treats `.gitignore`
as the source of truth for docs formatting scope: `make fmt-docs` formats
tracked and non-ignored files, while ignored local scratchpads, planning notes,
and operator-local artifacts stay out of formatter scans.

## Behavior changes

- **Single-selector output order is now a public contract.** Existing consumers
  can rely on source-document ordering and `_runtime.record_num` semantics for
  regular DOM, streaming, and indexed parallel extraction when the recipe has
  one record-boundary selector.
- **Multi-selector recipes remain selector-major.** Their `record_num` values
  are stable for current recipe semantics, but they are not a global
  document-order contract across selectors.
- **Index build writes incrementally.** JSON and seekable-zstd index writers no
  longer require the full record metadata slice before durable output
  generation.
- **Docs formatting respects ignore rules.** Ignored scratchpads and local
  planning notes are no longer scanned by `make fmt-docs`.

## Deferred

- **Bounded end-to-end JSONL/NDJSON output streaming** remains future work.
  v0.1.7 includes the contract and sequential primitives; command paths still
  buffer extracted records per source file before output.
- **Parallel sink integration** remains future work. The parallel aggregator
  still needs bounded ordered emission into a sink before the parallel path can
  make a bounded-output memory claim.
- **Incremental Parquet writing** remains future work. Parquet output is a
  secondary projection path and may buffer rows unless a future implementation
  adds true incremental row-group writing.
- **DuckDB, Arrow, service health endpoints, Prometheus metrics, adaptive
  backpressure, and repair modes** remain roadmap items.

## Upgrade notes

- **Version bump.** `VERSION` is `0.1.7`. Binaries from this tag emit `v0.1.7`
  via `sumpter version`.
- **Go installation.** v0.1.7 requires Go 1.26 or newer. After the tag is
  published, install with:

  ```bash
  go install github.com/fulmenhq/sumpter/cmd/sumpter@v0.1.7
  ```

- **Output ordering.** Single-selector consumers may use `_runtime.record_num`
  as the source-position field. Do not assume gapless numbers after filters.
- **Memory expectations.** Keep existing capacity planning for extraction
  output buffering. The record-sink contract is present, but bounded
  end-to-end JSONL/NDJSON output streaming has not shipped yet.
- **Release ceremony.** Use `SUMPTER_RELEASE_TAG=v0.1.7` for release targets.
  Tagging and pushing `v0.1.7` should happen only after CI, review, and the
  out-of-band public-surface/confidentiality checks are complete.

## Validation summary

The v0.1.7 cycle was validated through normal PR gates and final release-prep
checks:

- Public-surface genericization and repository-facing confidentiality cleanup.
- Document-order emission and `_runtime.record_num` regression coverage.
- Record-sink contract review and sequential sink primitive tests.
- Streaming index writer tests for source-byte hashing, malformed input,
  start-failure rollback, and multi-writer commit-failure rollback.
- Formatter-scope checks proving ignored scratchpads stay out of `fmt-docs`.
- Release prep: version bump, release notes, changelog, embedded docs refresh,
  `make check-all`, and `make pr-final`.

Before tagging, CI must be green on the release-prep PR and the required
out-of-band security/confidentiality scans must be complete.
