# v0.3.5 — Integrity-bound inputs and durable aggregate commits

**Released:** 2026-09-20 · **Lifecycle:** alpha (interface-stability track; external contributions welcome)

v0.3.5 strengthens multi-input extraction at both ends of the workflow.
Batch lists can declare the expected size and SHA-256 of each input, local
aggregate output commits durably by default, and aggregate NDJSON can opt into
row-to-input identity bound to the exact bytes parsed.

**Start here:** [`docs/extract-workflow.md`](../extract-workflow.md)
([input selection](../extract-workflow.md#input-selection-batch-lists-directories-large-trees)
and [aggregate output](../extract-workflow.md#aggregate-output-mode---output-mode-aggregate)).

## Change set

- **Runner and dependency refresh** — merge `78cf4edd1ee44bc08fa419c47117888ddd28938d`
  updates the CI/release tools runner to `v0.5.6`, advances
  `golang.org/x/net`, `x/sys`, and `x/text` as a set, and pins
  `github.com/klauspost/compress` at `v1.18.7` (#168).
- **Integrity-bound file lists** — merge `3a04943b49a9706d9421c45279e136902244a102`
  adds strict `{uri,size,sha256}` object lines alongside URI-only list entries.
  Sumpter verifies a private snapshot of the exact bytes it parses and fails
  before emitting records from an input whose declaration does not match (#169).
- **Durable aggregate commit and row identity** — merge
  `6de2e5af4dd55ea649286c7ead7a01b82bc90196` makes local aggregate commits
  crash-durable by default and adds opt-in `_runtime.input_ordinal` plus
  `_runtime.input_sha256`. The manifest publishes last as the per-recipe reader
  marker; incomplete identity accounting cannot publish a successful marker
  (#170).

## Compatibility & recovery

- URI-only `--file-list` lines remain valid. Integrity declarations are opt-in
  and may be mixed with URI-only lines while preserving list order.
- Row identity is opt-in and aggregate-NDJSON-only. Runs that do not select
  `--emit-input-identity` keep the existing row shape.
- Crash durability is now the local aggregate default. The explicit
  `--no-durable-commit` escape hatch is limited to supported local aggregate
  output and retains weaker publication semantics.
- Fail-fast prevents a recipe's uncommitted aggregate work from publishing a
  successful marker with a shortened inventory. It does not retract sibling
  recipes that already committed or a recipe whose manifest already renamed.
- A final directory-sync failure after manifest rename is an **unconfirmed**
  invocation. Inspect and reconcile the destination or retry into a fresh
  destination; do not infer success from marker presence alone.
- **Platforms:** unchanged — linux amd64/arm64, darwin **arm64**, windows
  amd64/arm64. Intel-Mac users build from source.

## Validation and dependency note

CLI help for `extract files`, `recipes run extract`, and
`recipes run extract-multi` documents integrity-bound file-list object lines,
`--emit-input-identity`, and `--no-durable-commit`.

`goneat dependencies --vuln` still reports high-severity advisories in
transitive gRPC and go-git paths reached through gonimbus test/tooling edges;
those paths are not linked into `cmd/sumpter`. This known graph-wide residual
is documented rather than treated as a release hold. This release does not
claim graph-wide zero-high findings.
