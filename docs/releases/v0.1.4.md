# Sumpter v0.1.4 Release Notes (Draft)

**Release Date:** TBD
**Theme:** Extract integrity, DSL parser hardening, and recipe ergonomics
**Status:** In Development

## Overview

v0.1.4 tightens extract output integrity so successful runs always produce the
requested artifacts, including legitimate zero-record outputs. It also hardens
the validation DSL parser so quoted string literals can safely contain operator
text without changing expression structure.

## Behavior Change: Quoted String Literals in DSL Filters

DSL expression and filter parsing now treats operator characters inside quoted
string literals as literal content, not split points. This applies across
binary expressions, ternary expressions, simple filters, function arguments, and
accumulation filter routing.

Unterminated string literals now fail loudly during parsing. Bare unquoted
values that contain quote characters, such as `name == Bob's`, should be
written as quoted values instead, for example `name == "Bob's"`. Backslash
escapes are honored only for detecting the closing quote delimiter; string
values keep their existing raw interior bytes.

## Behavior Change: `min_occurrences`

`match_selectors[].min_occurrences` is now enforced by the extract command.
Selectors with `min_occurrences: N` where `N > 0` fail loud when a source file
yields fewer than `N` matches. The error names the recipe, selector index,
selector XPath, declared floor, actual count, and source file.

The schema default changed from `1` to `0`, so selectors that omit
`min_occurrences` continue to accept zero matches. Recipes that already carry
an explicit `min_occurrences: 1` from older generated starter configs now opt
into enforcement. Review those recipes and change the value to `0` only when
zero matches are expected for correctly typed inputs.

## Empty Output Contract

Successful extract runs write output files even when zero records are
extracted. JSONL outputs are zero-byte files. Parquet outputs are schema-only
files with zero rows. Successful manifests include zero-record entries in
`outputs[]` and `counts_by_record_type`; absence of a manifest indicates a
failed or non-writing run.
