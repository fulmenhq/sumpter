# Sumpter v0.1.4 Release Notes

**Release Date:** 2026-05-23
**Theme:** Recipe ergonomics, DSL evolution, extract integrity, and the first signed release pipeline
**Status:** Released

## Overview

v0.1.4 brings sumpter's accumulated improvements since the v0.1.2 release under a single tagged, signed release. The v0.1.3 and v0.1.4 development cycles shipped continuously to main; v0.1.4 is the first formal tag to incorporate that work, and it lands alongside a new hand-rolled release pipeline (minisign + optional PGP signing, checksum manifests, CI-built artifacts, manual signing ceremony).

Three threads dominate the user-visible changes:

1. **Recipe ergonomics.** Authors can now declare per-recipe parameters with CLI overrides, derive parameters from source paths, attach cadence metadata, and control how columns flow into Parquet outputs. The same parameter values are visible both as output columns AND as DSL expression variables.
2. **DSL evolution.** Ternary conditionals, string-handling functions (`lower`, `upper`, `normalize_space`), quoted-string-literal hardening, and recipe-parameter access in expression scope. The consolidated DSL reference now lives in a single canonical document.
3. **Extract integrity and provenance.** Zero-record extract runs now emit empty output artifacts (instead of silently omitting them), per-selector `min_occurrences` floors are enforced, runtime provenance is captured in sidecar manifests, and recipes carry an explicit `content_version` with a migration path.

The release also introduces the **first signed-release pipeline** for sumpter — see `RELEASE_CHECKLIST.md` for the operator runbook. Future releases will follow this ceremony.

## What's new

### Recipe parameters and ergonomics

- **`defaults.parameters.*`** — recipe authors declare per-recipe constants (string key/value) that become output columns on every extracted record (#18).
- **CLI parameter overrides** — `--parameter <key>=<value>` on `sumpter recipes run extract` overrides a manifest default (repeatable) (#18).
- **Source-path-derived parameters** — `defaults.source_extraction[]` can extract recipe parameters from regex matches against the source file path; explicit `parameters_required[]` lets recipe authors mark which keys must resolve to a non-empty value at extract time (#19).
- **Recipe parameters in DSL expression scope** — `defaults.parameters.<key>` values are now readable as variables in `field_mappings[].expression` evaluation, in addition to their existing record-map column emission (#34, SUM-020). A name collision between a declared parameter and an XPath-extracted (or previously-evaluated) field of the same name surfaces as an explicit fail-loud error rather than silent shadowing.
- **Cadence metadata** — `defaults.cadence` lets recipe authors declare run-cadence intent as a free-form string (`daily-rolling`, `weekly`, `weekly-2x`, `on-demand`, or operator-chosen vocabulary) that flows into the per-extract provenance record (#31, SUM-016).
- **Parquet withhold columns** — `defaults.output.parquet.withhold_columns` declares which columns flow through the substrate/partition path but are omitted from the Parquet output body (NDJSON continues to emit the full self-describing record). Closes the Hive/AWS-Glue partition-collision pattern at recipe-author time (#30, SUM-015).

### DSL evolution

- **Ternary conditionals** — DSL expressions now support `cond ? a : b` ternary syntax across `field_mappings[].expression` and filter expressions (#26).
- **String functions** — `lower(s)`, `upper(s)`, and `normalize_space(s)` are now available in DSL expressions; null-propagating; consistent with existing DSL evaluator type rules (#32, SUM-017).
- **Quoted-string-literal hardening** — DSL parsing now treats operator characters inside quoted string literals as literal content, not split points. Applies across binary expressions, ternary expressions, simple filters, function arguments, and accumulation filter routing. Unterminated string literals fail loudly during parsing (#27).
- **DSL reference consolidation** — the canonical DSL reference lives at `docs/dsl-reference.md` (v1.1, post-SUM-012). ADR-0004 cross-references the consolidated doc (#28).

### Extract integrity and output

- **Zero-record extract runs emit artifacts** — a successful extract run that finds zero matching records now writes empty output artifacts and manifest entries instead of silently omitting them. Downstream consumers can no longer mistake a successful zero-record run for a failed run with missing files (#25).
- **`min_occurrences` floor enforcement** — `match_selectors[].min_occurrences` now defaults to `0` (explicit opt-in for non-zero floors), and per-selector floors are enforced so aggregate record counts cannot mask a selector-specific violation (#25).
- **Parquet secondary output** — `output.parquet` declares a Parquet sink that ships alongside the default NDJSON output. Field-type rules from the recipe drive the Parquet schema; row groups are bounded for streaming-friendly writes (#23).
- **Grouped reconciliation hardening** — validator handling of grouped reconciliations is now safer against malformed input and clearer in error reporting (#24).
- **XPath compile/evaluate** — extract now uses the upstream `xpath.Compile`/`xpath.Evaluate` API rather than an ad-hoc selector parser (#4).

### Provenance

- **Runtime provenance core** — every extract run produces a provenance record capturing recipe `content_version`, recipe parameters (resolved values, including CLI overrides), and per-output sidecar manifests (#11).
- **Extract sidecar manifests** — `*.manifest.json` files ship alongside NDJSON/Parquet outputs, capturing per-output statistics, source attribution, and recipe lineage (#13).
- **Recipe `content_version` + `migrate` subcommand** — recipes carry an explicit content-version field; `sumpter recipes migrate` migrates older recipes to current schema (ADR-0006 PR-A, #9).

### Operations and CLI polish

- **`SilenceUsage` on runtime errors** — runtime errors (extract-time contract violations, schema failures, missing parameters) no longer dump the full cobra usage help after the actual error message. Genuine flag-parse errors still emit usage as before. Set at the root command, so all subcommands inherit (#29, SUM-014).
- **`inspect` generates starter extract configs** — `sumpter inspect --generate-extract` produces a starter `extract.yaml` from observed XML structure to bootstrap recipe authoring (#22).
- **Examples harness + replacement** — generic OSS-clean examples replace legacy examples; the examples harness runs them as part of CI (#20, #21).

### Dependencies and supply chain

- **Direct dependency refresh** — minor-version bumps on direct dependencies; pre-1.0 minor-bump risk evaluated per-bump; vulnerability scan + SBOM regenerated as out-of-tree artifacts under gitignored `sbom/` (#33, SUM-019).
- **gosec scan scope tightened** — module cache, vendored deps, and generated code are excluded from gosec scans (#10).
- **License compliance** — `.goneat/dependencies.yaml` policy enforced (no GPL-3.0/AGPL-3.0/MPL-2.0); permissive licenses (MIT/Apache-2.0/BSD/ISC/0BSD/Unlicense) allowed.

### Release infrastructure (new in v0.1.4)

- **Tag-driven CI release workflow** at `.github/workflows/release.yml`. Pushes to `v*` tags trigger lint, test, multi-platform release build, and GitHub Release publication via `softprops/action-gh-release@v2`.
- **Hand-rolled signing ceremony** — `RELEASE_CHECKLIST.md` documents the manual ceremony. Operator (@3leapsdave) runs `make release-clean → release-download → release-checksums → release-verify-checksums → release-sign → release-export-keys → release-verify-keys → release-verify-signatures → release-notes → release-upload`. Signing uses minisign (primary) + optional PGP. Manual ceremony introduces deliberate friction to prevent rubber-stamping.
- **Multi-platform release artifacts** — `make release-build` cross-compiles for linux/{amd64,arm64}, darwin/{amd64,arm64}, windows/amd64. CGO-free (the seekable-zstd compressed-index path lives under `//go:build cgo && seekablezstd` and is omitted from released binaries; consumers who want it build from source).
- **Provenance artifacts** — SHA256SUMS and SHA512SUMS manifests, minisign + optional PGP signatures, exported public keys, and the per-release notes file all ship as release assets.

## Behavior changes

- **DSL quoted-string parsing now strict.** Bare unquoted values containing quote characters (e.g., `name == Bob's`) must now be written as quoted values (`name == "Bob's"`). Unterminated string literals fail loudly during parse rather than producing surprising downstream errors. See `docs/dsl-reference.md §Grammar — Values` for the canonical reference.
- **`match_selectors[].min_occurrences` defaults to 0.** Recipes that previously relied on an implicit positive floor must now declare it explicitly.
- **Zero-record extract runs emit artifacts.** Pipelines that detected zero-record runs by file-absence must now check the manifest's record count instead.
- **Recipe parameter / record-field name collisions fail loud.** A `defaults.parameters.<key>` declaration that collides with an XPath-extracted (or previously-evaluated) field of the same name now errors at extract time rather than silently shadowing. Disambiguate via renaming. (A future configurable per-recipe collision policy may be introduced if fallback semantics earn a real use case.)

## Out of scope (deferred)

- **SUM-005 — Cloud URI I/O.** Cloud URI support for input/output paths (S3/GCS/Azure) is deferred to v0.1.5; it was gonimbus-tag-blocked through most of the v0.1.4 cycle and unblocked just as v0.1.4 closed.

## Upgrade notes

- **Version bump.** `VERSION` is `0.1.4`. Binaries built from this tag emit `v0.1.4` via `sumpter version`.
- **Go installation.** `go install github.com/fulmenhq/sumpter/cmd/sumpter@v0.1.4` works once the tag is published.
- **Recipe migration.** Recipes that depend on the pre-v0.1.4 behavior changes listed above need adjustment (mostly DSL quoted-string and `min_occurrences` items). Run `sumpter recipes migrate` to update older recipes to current schema.
- **Signed release verification.** Release artifacts ship with `SHA256SUMS`, `SHA512SUMS`, `*.minisig` signatures, optional `*.asc` PGP signatures, and the exported public keys. To verify:

  ```bash
  # Download artifacts + manifests + signatures from the GitHub Release page
  cd dist/release
  sha256sum -c SHA256SUMS              # checksums
  minisign -V -p sumpter-minisign.pub -m SHA256SUMS   # minisign signature
  gpg --verify SHA256SUMS.asc SHA256SUMS              # PGP (if PGP signature present)
  ```
