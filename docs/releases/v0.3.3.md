# v0.3.3 — Stock xpath module; interim pin retired

**Released:** 2026-07-27 · **Lifecycle:** alpha (interface-stability track; external contributions welcome)

v0.3.3 is a **dependency hygiene** patch. v0.3.2 corrected silent-wrong XPath
sign arithmetic with a reviewed interim pin of `github.com/antchfx/xpath` under
`./third_party/antchfx-xpath`. Upstream has since merged and tagged that
isolation fix:

| Upstream | Notes |
| -------- | ----- |
| [antchfx/xpath#124](https://github.com/antchfx/xpath/pull/124) | Merged 2026-07-17 — numeric operator operand context isolation |
| **v1.3.7** | Tag on the merge commit; release notes cite #124 |
| **v1.3.8** | Later tagged release that still carries the fix (Sumpter pin target) |

This cut:

1. Requires **`github.com/antchfx/xpath v1.3.8`** from the module proxy.
2. **Deletes** `third_party/antchfx-xpath` and the `go.mod` `replace`.
3. Leaves **`xmlquery` at v1.5.1** (unchanged).
4. Keeps extract hermetic regressions for the predicated-sum × context-sensitive
   factor class green against the stock module.

No new recipe surfaces, no process-run or data-artifact contract pin changes.

**Start here:** [`docs/extract-workflow.md`](../extract-workflow.md) (XPath
arithmetic section). Behavior for the silent-wrong class matches the v0.3.2
pin; only the supply path changes (stock module instead of a local tree).

## Compatibility & notes

- **Corrective path unchanged** relative to v0.3.2 for expressions that needed
  operand-context isolation; results should match the prior pin for that class.
- **Trailing vs factor-first:** both forms are correct on this binary. Prefer
  factor-first only when targeting older Sumpter builds that still used a
  vulnerable evaluator.
- **Platforms:** unchanged — linux amd64/arm64, darwin **arm64**, windows
  amd64/arm64. Intel-Mac users build from source.
- **Alpha:** interfaces may still change between minor releases; external pull
  requests are welcome.

## Deferred / follow-ups

- Nested item/polymorphic `internal: true` remains deferred.
- Process-run control socket / run-steering (unchanged from v0.3.1 / v0.3.2).
- Richer data-artifact validation and full semantic L3 claims (unchanged).
- Cloud range-reads, GCS/Azure, DuckDB/Arrow, service health endpoints, and
  repair modes remain roadmap items.
