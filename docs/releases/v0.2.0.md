# v0.2.0 — Cloud I/O, reference-table lookup, list-typed parameters, and parallel-extract correctness

**Released:** 2026-06-18 · **Lifecycle:** alpha (interface-stability track; external contributions welcome)

v0.2.0 is the first minor release after the 0.1.x line. It makes S3-compatible
**cloud I/O** first-class across the engine, adds **external reference-table
lookups** and **list-typed recipe parameters** for richer recipe-driven
classification and enrichment, and fixes a **parallel-extraction correctness**
defect — backed by a new race detector in CI.

## Headline features

### Cloud URI I/O (S3-compatible)

Extract sources and outputs may now be `s3://` URIs end to end — across `extract`,
`index`, and recipe runs — against any S3-compatible endpoint (AWS S3, MinIO, or moto
for tests). Cloud access uses named **credential handles**: handle _references_ in
recipe YAML and on the CLI, never secrets, resolved from a credentials config.
Provenance records the logical source/destination and the handle **name** only —
never signed URLs, endpoints, or secret material.

- Read sources and write outputs (and the provenance sidecar) over `s3://`, including
  parallel/record-index sources. (#78, #79, #80, #82, #83, #85)
- Credential-handle selectors validated by a shared slug rule. (#86)
- Anonymous (unsigned) reads of public buckets, read-only by construction. (#90)
- Truly-dry `--dry-run`: a cloud run validates and lists without acquiring or staging
  any object bytes. (#88)
- `inspect` reads cloud sources through the same shared read boundary. (#89)
- Cloud-I/O errors are classified (transient vs. fatal) and redacted at a single
  read/write seam, so no raw SDK error — or credential material — surfaces. (#91, #97)
- Resolved credential handle recorded in provenance for auditability. (#88)

### External reference-table lookup

Recipes can declare external **reference tables** loaded once per run and queried from
field-mapping expressions via two new DSL functions:

- `in_reference(table, field)` — membership (Pattern A);
- `lookup_reference(table, field, default)` — key→value enrichment (Pattern B).

Each table declares a source (a contained workspace-relative path **or** an `s3://`
object with a `credentials_handle`), a format (CSV/TSV/NDJSON), its membership column
or key/value columns, and `max_rows`/`max_bytes` caps. A `--reference-table
name=source` override re-points a declared table's source for a single run without a
recipe edit.

Security model: local-path containment (absolute paths, `..`, and symlinks refused);
a cloud pre-read size cap so an oversized object is rejected before it can fill
staging disk; config-validation pre-flight (table names must be string literals
declared in the recipe; unknown/dynamic names fail before extraction); and
sidecar-only provenance that records each table's logical source, handle name, format,
mode, row count, and content hash — never row values. (#94, #95, #96)

### List-typed recipe parameters

Recipe parameters may now be **lists of strings**, with three predicates for set
classification in expressions: `starts_with_any`, `value_in`, and `string_length`. A
run-time `--parameter key='["a","b"]'` override supplies a list without a recipe edit;
a CLI value is treated as a list only when it is a valid JSON array of strings,
otherwise it stays a literal string. (#92)

### Parallel-extract correctness

Two data races on the parallel-extraction + index-streaming path are eliminated
(ownership/snapshot fixes, not locks):

- the streaming index store returns a **detached header snapshot**, so a caller may
  read header metadata (record counts, source) while records stream without the header
  being mutated under it — protecting both output and provenance integrity;
- each worker gets its **own compiled XPath plans**, so workers never share mutable
  evaluator state; the immutable reference-table registry and resolved parameters stay
  shared read-only (no per-worker copy).

A scoped `-race -count=1` gate over the parallel-extract and index packages (plus the
canonical repro) is now wired into CI to prevent regressions. (#98)

## Other fixes

- `--version` and `index build` metadata report the build-injected version regardless
  of the working directory. (#93)
- `make install` removes any existing binary before copying so the new binary lands on
  a fresh inode — avoiding the macOS/arm64 codesign inode-cache `zsh: killed` (SIGKILL)
  on reinstall. Removal failure is fail-loud; a missing target on first install is not
  an error.

## Compatibility & notes

- **Alpha:** interfaces may still change between minor releases; external pull requests
  are welcome.
- **Platforms:** the supported prebuilt matrix is unchanged from 0.1.10 — linux
  amd64/arm64, darwin **arm64**, windows amd64/arm64. Intel-Mac users build from source.
- **Cloud I/O:** authenticated access needs a credentials config (named handles);
  anonymous public-bucket reads need no credentials. Endpoints are S3-compatible; the
  reference test double is moto.
- **Provenance:** the sidecar manifest schema (`sumpter.provenance/v1`) gained an additive
  `reference_tables` block; existing manifests remain valid.
