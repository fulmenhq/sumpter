## Development Workflow

### Pre-Development Checklist

**BEFORE starting any development work:**

```bash
# ✅ Verify current lifecycle phase
cat LIFECYCLE_PHASE

# ✅ Check available quality gates
make help | grep -E "(check|test|coverage)"

# ✅ Verify Go environment
make check-go-env

# ✅ Review current coverage requirements
./scripts/validate-coverage-threshold.sh
```

### Standard Development Cycle

```bash
# 1. Start with clean state
make clean
git status

# 2. Make changes following patterns
# ... development work ...

# 3. Run quality checks
make check-all

# 4. Run tests with coverage
make test-coverage

# 5. Pre-commit validation
make pre-commit

# 6. Commit with proper attribution
git add .
git commit -m "feat: [description]

Generated by [Agent Name] under supervision of @3leapsdave

Co-Authored-By: [Agent Name] <noreply@sumpterhq.dev>
Authored-By: Dave Thompson <dave.thompson@3leaps.net>"

# 7. Pre-push validation
make pre-push

# 8. Push (ONLY with explicit authorization)
git push origin [branch]
```

## Quality Gates

### Phase-Aware Quality Gates

| Phase      | Coverage | Quality Checks         | Security                     |
| ---------- | -------- | ---------------------- | ---------------------------- |
| Alpha      | 50%+     | Basic (fmt, vet, lint) | gosec                        |
| Beta       | 70%+     | Standard + tests       | gosec + govulncheck          |
| Production | 80%+     | Full + integration     | gosec + govulncheck + manual |

### Automated Quality Gates

#### `make check-all` (Fast Quality Checks)

```bash
✅ Code formatting (gofmt)
✅ Import organization (goimports)
✅ Static analysis (go vet)
✅ Linting (golangci-lint)
✅ Security scanning (gosec)
```

#### `make pre-commit` (Lifecycle-Aware)

```bash
✅ All check-all validations
✅ Dynamic coverage validation
✅ Phase-appropriate coverage threshold
✅ Documentation formatting
✅ Test execution with race detection
```

#### `make pre-push` (Production-Ready)

```bash
✅ All pre-commit validations
✅ Integration tests (short mode)
✅ Security vulnerability scanning
✅ Multi-platform build validation
✅ Comprehensive test coverage
```

## Commit Procedures

### Commit Message Standards

**Format**: `type(scope): description`

**Types**:

- `feat`: New features
- `fix`: Bug fixes
- `docs`: Documentation
- `style`: Code style changes
- `refactor`: Code refactoring
- `test`: Testing
- `chore`: Maintenance

**Examples**:

```
feat: add XML streaming parser with encoding detection
fix: resolve memory leak in token decoder
docs: update repository operations SOP
test: add comprehensive PII redaction tests
```

### Attribution Requirements

**MANDATORY for all commits:**

```bash
# For AI agent contributions
git commit -m "feat: [description]

Generated by [Agent Name] ([Claude Code](https://claude.ai/code)) under supervision of [@3leapsdave](https://github.com/3leapsdave)

Co-Authored-By: [Agent Name] <noreply@sumpterhq.dev>
Authored-By: Dave Thompson <dave.thompson@3leaps.net> [@3leapsdave](https://github.com/3leapsdave)"

# For human contributions
git commit -m "feat: [description]

Authored-By: [Name] <email@domain.com> [@handle](https://github.com/handle)"
```

## Branch Management

### Branch Naming Convention

```
feature/[description-with-dashes]
bugfix/[issue-number]-[description]
hotfix/[critical-issue-description]
release/v[major].[minor].[patch]
```

### Branch Workflow

```bash
# Create feature branch
git checkout -b feature/xml-streaming-parser
# ... development work ...
git add .
git commit -m "feat: implement XML streaming parser"

# Keep branch updated
git fetch origin
git rebase origin/main

# Push for review
git push origin feature/xml-streaming-parser
```

## Lifecycle Phase Awareness

### Phase-Specific Requirements

#### Alpha Phase (Current)

- **Coverage**: 50% minimum
- **Focus**: Core functionality and professional tooling
- **Quality Gates**: Basic checks + dynamic coverage
- **Authorization**: Required for architectural changes

#### Beta Phase (Next)

- **Coverage**: 70% minimum
- **Focus**: Feature completion and integration testing
- **Quality Gates**: Standard checks + integration tests
- **Authorization**: Required for API changes

#### Production Phase

- **Coverage**: 80% minimum
- **Focus**: Enterprise readiness and performance
- **Quality Gates**: Full validation + security scanning
- **Authorization**: Required for all changes

### Phase Transition Procedures

**Alpha → Beta**:

1. Feature completeness validation
2. 70%+ coverage achievement
3. Integration test suite completion
4. Architecture review approval

**Beta → Production**:

1. Enterprise deployment validation
2. Performance benchmark completion
3. Security audit completion
4. Documentation completeness

## AI Agent Guidelines

### 🚨 CRITICAL: Push Authorization Protocol

**AI agents are PROHIBITED from pushing to remote repositories without explicit authorization.**

#### Required Authorization Process

1. **Before any push operation**:

   ```bash
   # ❌ NEVER DO THIS
   git push origin main

   # ✅ ALWAYS get authorization first
   # Contact @3leapsdave for push authorization
   ```

2. **Authorization Checklist**:
   - [ ] Supervisor approval obtained (@3leapsdave)
   - [ ] Quality gates passed (make pre-push)
   - [ ] Coverage requirements met
   - [ ] Security scanning completed
   - [ ] No sensitive data in commits

3. **Push Command (Only After Authorization)**:
   ```bash
   # Only execute after explicit authorization
   git push origin [branch-name]
   ```

## Emergency Procedures

### Rollback Protocol

```bash
# 1. Identify problematic commit
git log --oneline -10

# 2. Create rollback commit
git revert [commit-hash]

# 3. Run quality checks
make pre-commit

# 4. Push with authorization
# Contact @3leapsdave for approval
```

### Incident Response

1. **Stop all automated processes**
2. **Assess impact and scope**
3. **Contact technical supervisor (@3leapsdave)**
4. **Follow documented rollback procedures**
5. **Document incident and resolution**
